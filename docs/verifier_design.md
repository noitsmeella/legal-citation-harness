# 검증기 설계서 (B층)

## 하는 일

주장 한 문장과 판결문을 받아, 그 주장이 **올바른 주체의 말로** 판결문에 있는지 판정한다.

```
주장 ──► [1 후보 검색] ──► [2 역할 부여] ──► [3 내용 일치 판단] ──► [4 판정] ──► 판정 JSON
판결문 ─┘
```

| 단계 | 함수 | 첫 버전 | 개선 후보 |
|---|---|---|---|
| 1 후보 검색 | `retrieve_candidates` | 글자 2-gram 겹침 | 임베딩 검색 |
| 2 역할 부여 | `role_tagger.tag_rule` / `tag_llm` | 사람 라벨 → 규칙 | 모델 분류 |
| 3 내용 일치 | (verify 내부) | 모델에게 예/아니오 질문 | 함의 판정 모델 |
| 4 판정 | `decide` | 역할 비교 규칙 | 확신도 기반 ABSTAIN |

## 판정 규칙 (주장 대상이 법원일 때)

| 내용이 일치하는 문장의 역할 | 판정 |
|---|---|
| HOLDING 또는 REASONING 있음 | SUPPORTED |
| 그 외 역할만 있음 | MISATTRIBUTED (경고에 역할 명시) |
| 없음 | UNSUPPORTED |
| 법원 문장과 다른 역할 문장이 상반됨, 또는 확신 낮음 | ABSTAIN (v2에서) |

## 비교 실험

| 설정 | 역할 정보 | 역할 출처 |
|---|---|---|
| 기준선 | 사용 안 함 | |
| 상한 | 사용 | 사람 라벨 |
| 실제 | 사용 | role_tagger |

"상한"과 "실제"의 차이가 역할 자동 분류의 비용이다.

## 평가 데이터

`data/claims/` 주장 쌍. 문항 하나당 SUPPORTED 1개 + MISATTRIBUTED 1개, F 유형에서 UNSUPPORTED.

## 미정 사항

- 주장 대상이 PARTY인 주장(예: "피고인은 정당방위를 주장했다")의 판정 규칙
- 보충의견을 법원 쪽 근거로 볼지
